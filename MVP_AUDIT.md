# Аудит SmartInspect перед инвестиционным MVP

Дата аудита: 9 ноября 2026. Ветка: `feat/investor-mvp`.

## Архитектура (фактическая)

- **Next.js 15 (App Router) + React 19 + TypeScript.** Отдельного Node.js API нет: сервер — это route handlers в `app/api/*` того же приложения.
- **PostgreSQL (Neon)** используется только для заявок на демо (`/api/demo`, `/api/leads`). Если `DATABASE_URL` не задан, заявки пишутся в файл `.data/leads.json`.
- **Личный кабинет** (`/dashboard/*`) до аудита работал на статичных моках из `lib/dashboard.ts`; любые изменения (статусы, «прочитано», отчёты) жили только в памяти страницы.
- **Авторизация кабинета** — демонстрационная, в `localStorage` браузера (`lib/auth.ts`, `components/AuthProvider.tsx`); сервер о пользователях не знает. Серверная авторизация есть только у админки заявок (`LEADS_ADMIN_TOKEN`, httpOnly-cookie).
- **Карта** — MapLibre + MapTiler (`components/MapView.tsx`).
- **Деплой** — Docker-образ собирается в GitHub Actions и по SSH загружается на FirstVDS (`.github/workflows/deploy.yml`); тестов нет, гейт — `npm run check` (lint + build).

## Заглушки до доработки

- Моки объектов, инспекций, дефектов, оповещений и отчётов с независимыми числами.
- TXT вместо PDF, фиктивные размеры файлов.
- Неподтверждённые KPI аналитики.
- Одинаковое фото-заглушка у всех дефектов (исправлено ранее, до аудита).

## Принятые архитектурные решения

- **Хранилище кабинета — браузер** (решение заказчика): единый детерминированный демо-набор `lib/demo/seed.ts`, состояние в `localStorage` через `components/DemoDataProvider.tsx`, кнопка «Сбросить демо». Серверная БД для кабинета не вводилась — это отдельная задача вместе с настоящей авторизацией.
- **Все показатели — производные** от одного состояния (`lib/dashboard.ts`: `objectMetrics`, `dashboardStats`, графики).
- **Анализ изображений — отдельный сервис** с контрактом `AnalysisEngine` (`lib/analysis/types.ts`) и демо-реализацией по SHA-256 подготовленных снимков.
- **PDF — на сервере** (`pdfkit`, шрифт Inter с кириллицей), данные присылает браузер.

## Задачи

**P0:** единая модель данных; исправление дат и формулировок; создание инспекции; загрузка снимков; демо-анализ с разметкой; связь инспекций, дефектов и объектов; реальные PDF и скачивание; маркировка демо-показателей; сохранение состояния.

**P1:** фильтр периода и кликабельные KPI; объяснение индекса; история статусов; фильтр по объекту; калькулятор экономии; приоритетные действия; предпросмотр PDF; шрифт с кириллицей; ширина под 1920 px.

**P2:** сравнение «до/после»; ручная корректировка разметки; геометрия дорог на карте; точки дефектов на карте (нет достоверных координат); серверная БД кабинета и авторизация; подключение реальной модели.

Статус выполнения — в `MVP_CHANGELOG.md`.
